# Living roadmap

GitHub Issues are the source of truth for delivery. This document defines the phase taxonomy and maintenance policy.

## Phases

1. Foundation and core registry
2. Reviews, verification, trust scoring, and reputation
3. MCP registry, AI skills, agents, models, APIs, and interoperability
4. Security scanning, vulnerability intelligence, and continuous monitoring
5. Enterprise procurement, governance, and evidence operations
6. Government, compliance, sovereign deployment, and assurance
7. Explainable recommendation engine and assistant
8. Marketplace and commercial ecosystem
9. Mobile applications
10. Research and future expansion

## Issue contract

Every roadmap issue includes objective, business value, acceptance criteria, dependencies, estimated effort, technical considerations, and future enhancements. Issues carry a phase label and a capability label.

## Maintenance policy

- New ideas become issues; they are not discarded or hidden in chat or code comments.
- Link prerequisites and related work in issue bodies.
- Architectural changes require an ADR and documentation update in the same delivery.
- An issue is complete only when implementation, tests, security impact, API contracts, and user-facing documentation are current.
